别神话 Skill，值钱的是背后的工作方式

随着模型能力的提升，我也是建议大家尽量少用那些复杂的skill。我觉得大家可能都深有体验，那些吹得天花乱坠的各种skill装了一堆，结果自己用起来，好像也没啥特别大的提升。我一直是建议大家要先捋清自己的工作流，而不是盲目地套用他人的，不管什么大神不大神的。

这半年这个风气特别盛，很无语，好像人人都在攒 skill、分享 skill、收藏 skill。好像只要给 Agent 喂一个写得漂亮的 .md 文件，它就能突然靠谱、懂事、不犯浑。有人甚至把它当成治理 Agent 失控的铁律，业务需求说不清就加个澄清 skill，代码老写错就加个评审 skill，流程跑飞就加个约束 skill。最后token跑了一大堆，效果又没好多少。

skill 本身不生产能力，它只是把已有的能力复制了一遍。你该去学习的，是它背后那个人平时怎么干活。

Skill 是什么，又不是什么

先把话说白。Skill 是把隐性工作方法显式化，把某个会干活的人脑子里那套流程，写成 prompt、步骤、约束和工具调用，让 Agent 也能照着走。这件事本身很有价值，它让好方法可复制、可分发。

但 skill 解决不了你原本就不会的问题。

这是个特别容易绕进去的误区。很多人以为，给 Agent 加一个需求澄清 skill，它就会自己把需求问清楚。错。那个 skill 之所以有用，是因为设计它的人，本来就有把需求问清楚的一套方法，他把自己的习惯固化成了文件。你如果自己脑子里没有这套方法，抄来的 skill 也只是个空壳，Agent 照着念，问得表面、问不到点上，最后还是糊里糊涂开工。

看到惊艳的 skill，第一反应不该是”我也要装一个”。该问的是，这文件背后，那个人到底是怎么干活的。

grill me，被当成提问技巧，其实是耗尽不确定性的纪律

第一个例子，grill me。

表面上看，这是个让模型不停向你提问、直到双方都明确才动手的 skill。很多人觉得新鲜，模型学会反问了，好酷。但是我经常会碰到它过度提问，所以什么时候喊停，以及提问的边界，就是你个人能力了。

真正值钱的不是”模型会提问”这个动作，是它背后那条规定，在写第一行代码之前，把业务逻辑里的模糊、冲突、遗漏，全部逼出来。

开发也好，设计也好，这条规定太重要了。

你想，需求文档里轻飘飘一句”用户上传文件后做处理”。处理指什么，解析、压缩，还是识别分类？失败怎么办，重试还是报错？并发多少算正常？敏感文件合规怎么过？这些但凡有一个没想清，你写完代码才发现理解错了，而改的成本，比开工前问清楚高十倍。

grill me 干的事，就是逼你把这些都想透，再动手。它把先对齐、再执行变成了一种强制流程。

学 grill me，别只学让模型提问。你要学的是，动手前先把不确定性耗尽。这条纪律，你关掉那个 skill 文件也该带着走。

superpower 的 TDD，借鉴思路，别照搬形式

第二个例子，superpower 那类把测试当驱动的工作流。

它的做法是先写测试、定义做完长什么样，再写实现去满足它。思路是真的好，给每个阶段一个可验证的标准，而不是闷头写到尾才发现有问题。 它还强调每个阶段要有阶段性报告，这点在和 Agent 协作时尤其关键，因为你自己也得知道它干到哪了、干得对不对。

实际用起来，你会发现这个skill给你写了一堆的test，会非常慢，也是一种负担。尤其是每次验证个啥还得给你跑一堆回归测试。其实很多测试是完全没必要写的。

我在另一篇里专门写过测试这件事，测试不是奖状，是刹车；不是装饰，是方向盘。 越早的测试越快、越窄、越便宜；越晚的测试越少、越重、越贴近真实。探索期、原型期，你根本不知道最终形态长啥样，这时候每行代码配三个测试，纯属负资产。不要被 TDD 的形式绑死，半天憋不出一行能跑的业务逻辑，全在跟测试框架较劲。

该借鉴的（思路） 别照搬的（形式）
动手前先想清这一步做完算成功的标准 强制每行代码配 N 个测试
每个阶段留一个能让人、让模型检查的产出 不管阶段轻重都写满测试套件
阶段性报告，让协作双方始终对齐 为了像 TDD 而 TDD

你不需要真的 TDD，但你需要在动手前知道这一步成功的样子，并在每个阶段留一个能检查的节点。思路拿走，形式看情况扔。你该借鉴的是那份先定标准再动手的纪律，不是那份红绿测试通过的仪式感。

怎么学一个 skill

看到好 skill，别急着收藏。先问自己三件事。

  1. 它把哪种隐性工作方法显式化，是把模糊变清晰，是分阶段交付，还是设了验证点？
  2. 这个方法，在我自己的活里卡在哪，是需求老理解错，还是写到一半才发现方向偏了？
  3. 我能把它剥离成习惯吗，不依赖那个文件，我也用得上吗？

真正被你吸收的 skill，是你关掉文件也还会那么干的那套动作，开工前先对齐、每个阶段留检查点、做完有可验证的标准、对外给结论前先证真伪。

这些动作一旦变成本能，你写不写那个 skill 文件，活都干得扎实。

Skill 是皮，工作方式是骨。文件能复制，本能复制不了。好的 skill 让人更早知道自己该在哪慢下来，这类越多越好；帮你省得想的那种，留着反而危险。

下次再看到一个惊艳的 skill，先别点收藏。先问一句，它背后那个人，平时是怎么干活的？答案，往往比文件本身值钱得多。这套看人、而不是看文件的本事，可能会变得越来越重要。
