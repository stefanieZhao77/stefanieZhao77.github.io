# 以后公司雇佣的，是你自己的 Agent

前两天看到一个很酷的项目叫 HashAgent。你打开一个网页，里面就是一个 agent，它跑在你的浏览器里，靠 WebGPU 调用本地显卡，不需要服务器，不需要装环境。最特别的是，这个 agent 可以被存成一个 URL。你改完它的提示词、它的工具、它的边界，把链接发出去，别人点开，跑的就是你调过的那一个。agent 正在变成一种可以携带、可以分享、零部署的轻量单元。而一旦 agent 变成这种单元，它天然就会是「个人化的」。我一直认为未来的工作雇佣方式，会从雇佣个人变成雇佣个人的 agent，这个项目让我看到了我这个预言的可实现性。

## 一个 agent 单元里装的是什么

一个能存成 URL、能在本地跑的 agent，它装的除了能力，还有写它那个人留下的痕迹。

你挑了哪些工具，接了哪些数据源。你给模型设了什么边界，哪些事它不能擅自做。你偏向哪种回答，遇到拿不准的情况让它怎样处理。这些东西拼起来，就是这个 agent 的「性格」。两个人用同一个模型，调出来的 agent 不会一样，因为底座相同，写进去的那个人不同。

这正好印证了我之前一直想讲的一个判断：技术人的竞争力，正在从「你会用什么工具」转移到「你能把自己的品味和工作方式写成可复用的东西」

agent 的未来形态，是带着你个人印记、能被打包带走的单元，不是又一个更大的模型。

## 雇佣的单位变了

那么「雇佣」这件事会怎么变。我把两种单位放在一起比一下。

| 维度 | 雇一个人 | 雇一个人的 agent |
|---|---|---|
| 携带方式 | 简历、面试、试用期 | 一个 URL、一份配置、一段可运行的代码 |
| 能不能提前验证 | 难，得共事才知道 | 能，把任务丢给它跑一遍就知道 |
| 边界谁定 | 合同和自觉 | 写进 agent 的提示词和权限里 |
| 离职带走什么 | 人和经验一起走 | 配置留下来，下一家用同样的单元接着跑 |
| 替代成本 | 招人、培训、磨合 | 换底层模型，行为不变 |

这张表不打算证明人会被淘汰。它想说的是，当 agent 变成一个可携带、可验证、边界写死的单元，公司买到的就不再是「一个人的时间」。公司买到的，是一种被验证过的执行能力。而这份能力，长着写它那个人的样子。

公司雇佣的，会变成「人加上他那个独特的 agent」。人负责判断和担责，agent 负责把判断变成稳定、可复现的动作。两者的组合，才是新的工作单位。

## 为什么它必须待在你这边

这也解释了为什么我把「本地 agent」看得这么重。agent 要带着你的印记跑，它就不能住在不归你管的服务器上。WebGPU 在浏览器里跑、模型在本地常驻，这些事看着是技术偏好，底下是一个更硬的要求。你的 agent 装着你的品味和边界，它得在你能控制的地方。

本地模型的兴起，和「agent 作为个人单元」是同一股劲的两头。一头是模型能跑在你自己的机器上，一头是 agent 能被你打包带走。

有人会觉得，这不就是「AI 取代人」换了个说法。我的判断是，它顶多顶掉「只出卖时间的人」。一个只会重复执行、不留下自己印记的人，确实会被一个写好的 agent 替掉。但一个把自己的品味、判断、工作流都写进 agent 的人，他会变得比以前更贵，因为现在他能同时管十个这样的单元，产出以前十倍的东西。

这里有个我还没想到成熟方案的地方，agent 作为「个人单元」能携带，也意味着它能被盗用、被仿制。你的品味写成了文件，别人复制一份就能用。这个问题我今天给不出答案，因为到现在为止，连短视频被洗稿这种事情都没办法被正常保护，agent 可能会更难。
