RSI 是 Recursive Self-Improvement，中文叫“递归自我改进”。关键在于，一轮改进不仅让 AI 更会做某项任务，还让它更擅长完成下一轮改进。上一轮的成果重新进入研发过程，形成反馈。

举个例子：一个 AI 找到更有效的训练方法，用它训练出更强的后继模型；后继模型因此更会设计实验、判断结果，又找到下一项有效改进。说白了就是AI自我迭代改进。改进对象可以是权重，也可以是算法、训练流程或研究工具，不要求同一份模型直接修改自己。不过，反馈能否持续、加速到什么程度，还取决于算力、实验和验证的瓶颈，不能直接等同于无限增长。

权重编辑是这个方向的一条候选路径。我们已经习惯让 Agent 改代码了。描述问题，把仓库交给它，让它检查实现、提出修改、运行测试。现在，如果把仓库换成一个神经网络的权重文件，这套工作方式还能不能成立？MIT CSAIL 团队在 2026 年 11 月 2 日发布的 [Weight Space Programming 研究博客](https://rikiyat.github.io/blog/weight-space-programming/)，就在尝试这件事。他们让 GPT-6 Astra 分析、编写和修改其他网络的权重，其中一个实验是修补 Qwen3.5-0.8B 的数学表现，修改过程不使用梯度更新。

## 权重到底是什么

可以把语言模型简写成一个函数：

`输出 = f(输入上下文, θ)`

这里的 θ 就是权重。它们是大量浮点数，组织成不同层里的矩阵和向量。输入经过这些计算，最终变成下一个 token 的概率分布。

平时写 prompt，改变的是输入上下文。给模型加角色说明、放几个例子、要求逐步推理，都在这一侧。常见的 RAG 应用先检索材料，再把材料交给模型，也主要改变这一轮能看到什么。它们可以显著影响输出，但推理时不必修改生成模型的权重。

训练和微调改变的是 θ。我们定义损失函数，用样本计算误差，再让优化器沿梯度更新参数。LoRA虽然冻结原有权重、只训练低秩增量，仍然属于这条路线。

Weight Space Programming 尝试让 Agent 根据任务目标和反馈，直接决定怎么改 θ。梯度下降负责产生更新的那个位置，现在有一部分交给了能分析问题、编写程序的模型。不用梯度，依然可以有优化。先试一个修改，测效果，不行再换。不使用反向传播，不等于没有计算、数据和试错成本。权重也不是一张知识表。改权重更像调整一个计算过程，修改后会影响哪些输入，需要实际检查。

## 模型究竟卡在哪里

理解 Qwen 的实验，可以先不看公式。研究者发现，这个小模型的很多失败，不是算出了错误答案，而是一直重复前面的推理，直到用完允许生成的长度，还没把答案交出来。

Agent 要找的，因此不是“把正确答案写到哪里”，而是：模型内部是否有一些计算，会不断加强这种重复倾向？找到以后，能不能调整这些计算，让模型更容易继续往下推理？

最后，它改动了两层中的一小部分连接。没有把整个模块关掉，而是针对这些连接中与重复推理有关的作用做调整，尽量保留其他计算。具体来说，这次修改涉及约 13 万个权重，只占整个模型的约 0.016%。不过，动到的地方虽然少，局部调整的幅度并不小。

0.016% 说的是改动数量，不是影响范围。语言模型每生成一段内容，又会把它放回后续上下文；一旦不断写出相似的检查和重述，后面的生成还可能继续沿着这个模式走。因此，一个局部补丁也可能改变后面很多内容的生成。

## Agent 实际上怎样改

在这个实验里，Agent 可以读取权重、编写 Python，让外部工具执行修改，再观察模型做题的结果。可以把它理解成一边维修、一边试运行：先看模型卡在哪里，提出原因，试一个补丁，再让修改前后的两个版本做同样的题，比较究竟有没有改善。

这里最有价值的部分，是把“接下来该试哪里”交给了一个有编程和推理能力的搜索者。常规自动调参往往在人预先规定的几个旋钮之间搜索，例如学习率、层数或温度。一个可以写程序、分析权重的 Agent，有机会提出原先没有列进配置表的修改。

不过，研究者也给了明确的诊断起点：提示可以把“重复思考、迟迟不结束”作为修复目标，还要求试验不同的修改强度，并保留没有参与选择补丁的题，最后才用来验证。Agent 自己寻找具体位置和修改方式，整个故障排查框架仍然由人设计。它也可能把偶然有效的操作解释得很漂亮，所以解释和效果仍然要分开验证。

这轮编辑有 50 次使用前向评测工具的机会，并不是只做了 50 道题，一次生成评测最多可以包含 512 个样本，也不是整个过程只调用 Agent 50 次。它先用练习题探索和验证补丁，最终成绩再由研究者用另一批评测题计算。

## 修好以后，模型变强了多少

在研究者这套开启 thinking、最多生成 32,768 个 token 的评测配置下，MATH-500 的正确率从 7.9% 提升到 48.1%，GSM8K 从 13.8% 提升到 67.1%。MATH-500 中耗尽长度预算的回答比例，则从 93.0% 降到 33.1%。

原本能继续算下去的题，如果一直重复、耗尽输出预算，最后仍然拿不到有效答案。让这条路径顺利结束，已经足以提高正确率，不需要假设凭空写入了整套数学知识。

这也是我看这个实验时最在意的点，模型可能缺少解题能力，也可能已经有一部分能力，却经常无法把过程完成。两种问题，修改权重的方式可能不相同。

研究者还试了较少陷入重复循环的 Gemma 3 270M，却没有得到明确的数学能力改善。这个对照提醒我们，拆掉妨碍能力发挥的障碍，与增加原本缺少的能力，是两件不同的事。这组实验展示了前一种可能，还没有解决后一种问题。

## 从模型补丁到递归改进 还差哪一步

直接修改权重并不是第一次出现。Weight Space Programming 让我感兴趣的地方，是更通用的模型开始参与寻找和编写这些修改，而不只是执行人已经设计好的编辑算法。

要继续往前走，我认为最关键的证据是：第一轮改进之后，系统下一轮做研究、提出修改和判断结果的能力，也确实提高了。只让同一个强模型不断修补小模型，可以是很有用的自动化研发，还没有展示“改进能力本身得到改进”的反馈。

而且，这个反馈需要在多轮以后仍然成立。分数上涨不能来自评测越来越容易，前几轮保留下来的能力也不能在后面逐渐丢失。这些条件比“能改自己的某几个浮点数”更难验证，也更值得花时间。

对工程实践，我反而更期待另一个用途：让模型故障也能进入相对具体的诊断流程。有失败样例，有关于内部机制的假设，有可保存、可回滚的权重补丁，再用独立测试确认哪些行为改善、哪些行为退化。

权重文件当然还远没有源码那么容易读。我们也还不能像审查一个普通函数那样，靠看补丁就知道它是否正确。但如果越来越多模型问题可以被缩小到某种计算路径、某组方向、某份可重复验证的修改，那么“这个模型就是不行”就不必总是讨论的终点。但是比起立刻把它解释成无限自我进化，我更想看到下一份结果：换一个模型，换一组没有参与搜索的任务，Agent 能不能再次找到有用的补丁，并清楚地证明它修好了什么。

## 技术补充：补丁具体改了什么

如果想进一步看权重层面的操作，可以用一个简化的 MLP 公式理解：

`h_new = h + W_down × a(h)`

`h` 是当前表示，`a(h)` 是 MLP 中间激活，`W_down` 把这些激活映射回模型使用的表示空间。这个式子省略了归一化等细节。把矩阵乘法拆开，`W_down` 的每一列都对应一个方向；某个中间单元激活得越强，那一列向量对结果的贡献就越大。因此，可以不删除整个单元，只改变它向后续计算传递的某个方向分量。

最终修改集中在第 15、19 层 MLP 的 down projection，各涉及 64 列，共 131,072 个权重元素，约占 0.016%。Agent 从成对的顺利推理与重复推理上下文构造各层的单位方向 `u`，选出最明显向对应方向写入信号的列，再做定向补偿：

`W = W0 − 6 × outer(u, mask64 × (u @ W0))`

`W0` 是原矩阵，`mask64` 只留下选中的 64 列，`outer` 表示外积。系数是 6，所以这比把某个方向的投影简单清零更强，包含了反向补偿。以补丁与原矩阵的 Frobenius 范数之比衡量，两处改动约为 10.6% 和 8.1%。全模型里改得稀疏，不等于被修改的位置只轻轻动了一点。

练习材料包括 GSM8K、MATH 的训练题及历年 AIME 题；一次前向工具调用也可以用于读取模型处理文本时的内部状态，而不生成答案。最终评测集不向 Agent 开放。
